Input Component - Basic Examples

This page demonstrates the basic usage of the Input component for collecting single-line text input from users.

NHS UK Design System Guidelines

Use text input to: Let users enter a single line of text

When to use: For names, email addresses, phone numbers, NHS numbers, or other short text

When NOT to use: For longer text (use textarea), dates (use date input), or multiple selections

Basic Text Input

A simple text input with a label for collecting user information.
<div class="public-good-form-group"> <label class="public-good-label" for="full-name">Full name</label> <div class="public-good-input-wrapper"> <input class="public-good-input" id="full-name" name="full-name" type="text"> </div> </div>

Accessibility Features

All input components include comprehensive accessibility support.
This input demonstrates key accessibility features including proper labeling, hint text association, and keyboard navigation support.

Accessibility Features:

  • Label association: Proper for/id relationship between labels and inputs
  • Hint text support: Uses aria-describedby to associate hint text
  • Error messaging: Screen reader accessible error announcements
  • Keyboard navigation: Full keyboard accessibility with proper focus indicators
  • Touch targets: Minimum 44px touch target size for mobile accessibility
  • High contrast support: Adapts to high contrast mode preferences
✓ Do
  • Use clear, descriptive labels
  • Provide helpful hint text when needed
  • Use appropriate input types (email, tel, etc.)
  • Size inputs appropriately for expected content
  • Include autocomplete attributes where relevant
  • Use proper error messaging for validation
✗ Don't
  • Use placeholder text instead of labels
  • Make inputs too small for their content
  • Use vague or unclear label text
  • Forget to associate error messages with inputs
  • Use text inputs for dates or selections
  • Disable copy and paste functionality
